## The broad problem

Characters in a game have to work across very different kinds of moments. Some are closely authored for a cinematic. Others need to respond immediately because the player is in control.

On Assassin’s Creed Origins, I worked on both cinematics and gameplay animation. This included the systems and character behaviors behind what the player sees moving on screen.

## Moving between contexts

One thing that stands out is that cinematic quality and gameplay responsiveness are not opposite goals. They simply expose different constraints. A cinematic can control timing and framing. Gameplay has to deal with changing input, state, direction, and context.

Working across both made the boundary between authored animation and systemic behavior easier to see. It also made transitions more important, because the character still has to feel like the same character when control moves between those contexts.

## What I carried forward

This project helped shape how I think about visible movement. The animation is what the player sees, but it is supported by state, timing, conditions, and decisions that are often invisible when everything is working correctly.

That is still the part of technical animation I find most interesting: building the structure underneath the motion, then using the result on screen to judge whether the structure is doing its job.

> The best systems disappear into the character. The player sees the behavior, not the machinery underneath it.
